# How's It — animated engineering explainer reels

Programmatic short-form videos (Instagram Reels + YouTube Shorts) built with
Remotion. Episode 1: "How Netflix Works". The channel explains how tech
systems and everyday machines work, faceless, with voiceover + motion graphics.

## Commands

- `npm run studio` — live preview (best for iterating on scenes)
- `npm run produce` — full post-audio pipeline: whisper transcribe → align → render → faststart remux. Run after replacing `public/audio/narration.mp3`.
- `npm run tts` — ElevenLabs API generation (requires PAID plan; free tier can't use library voices via API → generate in their web UI instead and save the MP3 manually)
- `npm run render` / `npm run still <out.png> --frame=N` — direct Remotion render
- `npm run analyze -- <video>` — script anatomy of any clip (extracts audio → whisper →
  pacing curve, beat map, hook shape, turn markers). `-- --episode <slug>` for our own,
  `-- --compare <a> --against <b>` to diff. Reports land in `analysis/`. Copy STRUCTURE
  from references, never wording — see the no-IP-imitation rule below.

**Before any topic/script work: read `CONTENT.md`** — it's the episode log
(what already exists — never repeat a covered topic) and the idea backlog with
pre-written hooks. Update it when an episode ships or ideas are added.
`ZACK-STYLE.md` is an experimental second script mode (chain-link causality,
zero-silence, cold ending) being A/B-tested against the default style — check
its experiment log when picking a mode for a new episode.

## Pipeline (per episode)

1. Create `src/episodes/<NNN-slug>/` with `script.ts` (narration + scene data), `scenes/` components, and an `index.ts` manifest; register it in `src/episodes/index.ts`
2. Narration MP3 → `public/episodes/<NNN-slug>/narration.mp3` (ElevenLabs web UI; voice: Brian "Relatable Everyman", v3 model, speed 92, stability ~26, similarity 75 — keep these settings for voice consistency)
3. `npm run produce` (defaults to latest episode; or `npm run produce -- <slug>`) — everything else is automatic
4. Watch `out/<slug>/final.mp4` before publishing (ALWAYS — QA gate)

## Architecture

- **Per-episode** (`src/episodes/<NNN-slug>/`): `script.ts` (narration/scene data), `scenes/` (scene components), `index.ts` (Episode manifest), `timing.json` (GENERATED by align.mjs — never hand-edit)
- **Shared**: `src/theme.ts` (red #e50914 accent, cyan secondary, galaxy bg) · `src/components/` (Background starfield, Chrome header+stepper, Captions karaoke, ui.tsx primitives) · `src/Root.tsx` (one Remotion composition per episode, id = slug)
- **Scripts** (all take optional episode slug arg, default = latest): `transcribe.mjs` (whisper → word timestamps, cached in `.cache/`), `align.mjs` (matches scene-opening words to find boundaries; builds caption lines), `produce.mjs` (transcribe → align → render → faststart remux), `tts.mjs` (ElevenLabs API, paid plan only), `analyze.mjs` (reference/episode script anatomy → `analysis/`)
- Episode audio lives in `public/episodes/<slug>/`; outputs in `out/<slug>/`

## Conventions & gotchas

- **Scene animation beats are hand-timed frame numbers** tuned to the narration pacing. If narration changes/re-generates, scene durations shift (align.mjs handles that) but internal beats may need manual nudging — check late-scene elements still fit within the new duration.
- **Final deliverable is `out/<slug>/final.mp4`** — 1440×2560 (Meta's recommended Reels res; ≥1440p gets YouTube's VP9 tier), uploaded to BOTH platforms. produce.mjs renders a 2160×3840 supersampled master (`raw.mp4`, CRF 15) then lanczos-downscales + faststart-remuxes — QuickTime shows a dead audio button on Remotion's raw output; the remux fixes it. Delivery encode must stay H.264 yuv420p, bt709 **tv-range** (a pc-range/bt470bg render once slipped out — colors shift after platform re-encode), AAC 48kHz, 30fps. **Safe margins — QA every episode's stills against all four sides** (comp space is 1080×1920; the master is that ×2). Verified 2026-08 against a real on-device IG Reels screenshot (UI positions measured in comp coords) + published IG/YT safe-zone guides: **top** no text y<269 (YT Shorts chrome is the driver; IG's own top bar ends ~y95); **left** x<65; **right** x>940 — NOT 1015: the IG action rail (like/comment/share) occupies x942–1004 × y1186–1788 and YT reserves 140px, so a full-width centered `Headline` must cap its text width to stay left of 940 in that y-band; **bottom** two hard lines, YT title/description overlay from y≥1500 and IG profile/caption row from y≥1734. The karaoke captions are the deliberate bottom exception and sit at `bottom: 420` in shared `Captions.tsx` — pill bottom edge lands at y1500, exactly on YT's line with zero slack, never lower. (Note: top/left match Meta's official Reels ads spec — 14%/6% — but our bottom is deliberately more lenient than Meta's flat 35% (y>1248), which is written for ad chrome; fine for organic posts, but **boosting a reel puts captions and closing headlines under the ad CTA band** — don't boost, or accept the overlap.) Scene-closing headlines/chips must end above ~y1370 to clear the caption pill. Also: IG scales the video to fit height and **crops the sides** — comp x<35 and x>1047 are not rendered on-device, so the 65px left margin is only ~30px of visible breathing room. Known violations as of 2026-08 (not yet fixed): shared `Chrome.tsx` header (top:96) + stepper (top:176) sit inside the top band on every episode; 003's closing headlines reach x≈995 under the action rail in 3/5 scenes and Hook's headline (top:1300) clears the caption pill by only 6px.
- Captions: karaoke reveal is the channel constant (unspoken ~30% opacity, spoken full, current word accent + slight scale pop). The *dressing* is per-theme via `theme.caption`: dark skins are boxless monospace; light `maps` skin uses a white rounded-pill card with bold sans to match its chip language. No multi-color word accents — user prefers minimal/elegant.
- **Theming (per-episode skins)**: visual identity is deliberately NOT fixed. `src/themes/` holds named skins (`galaxy`, `blueprint`) implementing the `ThemeSpec` token contract (colors + background variant + motion personality). Each episode picks its skin via `theme:` in its manifest. **Channel constants that never change**: typography (`FONTS` in `src/theme.ts`), caption behavior, the stepper concept, icon/diagram style. **Rules**: components/scenes read tokens via `useTheme()` — never import a skin directly; new skins must implement every token; `brand*` tokens are for the episode's subject (Netflix red etc.); when designing a new skin, load the `design-for-ai:color` / `frontend-design` skills to build the palette properly, then save it as a new file in `src/themes/` and register it in `THEMES`.
- **Object art comes from the icon registry, not hand-typed paths.** Recognisable objects (toilet, hand, plane, truck, seat…) are Fluent Emoji flat glyphs (MIT) pulled offline into `src/icons/registry.json` via `npm run icon -- add fluent-emoji-flat:<name>` (`find <set> <q>` searches a pack; browse at https://icones.js.org/collection/fluent-emoji-flat). Render with `Icon` / `IconPaths` from `src/components/Icon.tsx`, ALWAYS `recolor` to the episode's color law, and wrap parts for per-piece shadows/pivots (012's `Lavatory`, `SeatRow`, `ServiceTruck`, `HandPress` in `scenes/kit.tsx` are the reference). Hand-code SVG only for geometric things (pipes, arrows, tanks, waves) and for objects the beat needs in a specific view (012's side-view plane with its window row). Only attribution-free sets (MIT/ISC/Apache/CC0); never `openmoji` (CC BY-SA). The 8.5 MB pack stays a devDependency — never import it from `src/`.
- **No IP imitation**: no cloned character voices (e.g. Rick and Morty), no mascots copied from other channels. Original content only — this is a policy/monetization requirement, not just taste.
- Renders must be deterministic: no `Math.random()`/`Date.now()` in components (Background uses seeded pseudo-random).
- `.env` holds `ELEVENLABS_API_KEY` (gitignored). Voice ID for API use: `gPPH6SLdL8XSX6GNJ40G` in `scripts/tts.mjs`.
